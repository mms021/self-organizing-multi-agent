# RFC-1800 — JSON Schema and Data Model

**Status: Draft**

**Version: 0.3**

### 1. Общие сущности

Agent, Capability, Role, Task, Message, Claim, Result, Verification, Knowledge, Artifact, Team, Project, ProjectMembership, ReputationEvent, Event, Error, Permission, Credential, Approval, AuditLogEntry.

Все сущности должны:

- иметь стабильный ID;
- иметь `schema_version`;
- иметь `timestamp`;
- поддерживать расширение через `metadata`/`extensions`;
- сохранять обратную совместимость там, где это возможно.

`schema_version` следует той же семантике `MAJOR.MINOR`, что и `protocol_version` сообщений (RFC-1100 §16): MINOR — обратно совместимое добавление опционального поля, MAJOR — breaking change, требующий согласования через `compatibility` в manifest (RFC-1000 §2).

### 2. Связи между сущностями

- `Task.team_id` → Team, `Task.project_id` → Project (RFC-1250 §10);
- `Team.project_id` → Project, не более одного (RFC-1250 §10);
- `Role.context_id` → Task | Team | Project (RFC-1200 §2, RFC-1250 §9);
- `ProjectMembership.project_id` → Project, `ProjectMembership.agent_id` → Agent (RFC-1250 §7);
- `Claim.source`/`Result.artifacts`/`Verification.target_message_id` связывают эти сущности с исходным `Message` (RFC-1100 §5) и друг с другом;
- `ReputationEvent.agent_id` → Agent, `ReputationEvent.context_id` → Task | Team | Project (RFC-1500 §3);
- `Knowledge.references` и `Knowledge.supersedes`/`superseded_by` → Knowledge | Artifact | Task | Message (RFC-1300 §3);
- `Artifact.task_id`/`project_id` → Task | Project (RFC-1300 §7);
- `Permission.agent_id` → Agent, `Permission.context_id` → Task | Team | Project (RFC-1600 §3);
- `Credential.agent_id` → Agent, `Credential.rotated_from` → Credential (RFC-1600 §7);
- `Approval.requested_by`/`approver_id` → Agent, `Approval.context_id` → Task | Team | Project (RFC-1600 §8);
- `AuditLogEntry.context_id` → Task | Team | Project, `AuditLogEntry.details.approval_id` → Approval, если применимо (RFC-1600 §6).

### 3. Примеры

Полная схема envelope сообщения — RFC-1100 §5; полная схема Knowledge — RFC-1300 §3. Ниже приведены примеры остальных сущностей, чьи поля описаны как список в соответствующих RFC.

Пример Agent:

```json
{
  "agent_id": "agent-123",
  "schema_version": "1.0",
  "capabilities": [],
  "roles": [],
  "status": "READY",
  "load": 0.25,
  "reputation": {},
  "constraints": {},
  "metadata": {}
}
```

Пример Capability (RFC-1000 §5):

```json
{
  "capability_id": "capability-search",
  "schema_version": "1.0",
  "name": "web_search",
  "description": "...",
  "tags": [],
  "metadata": {}
}
```

Пример Role (RFC-1200 §2):

```json
{
  "role_id": "role-123",
  "schema_version": "1.0",
  "name": "coordinator",
  "agent_id": "agent-123",
  "context_id": "team-123",
  "granted_by": "self",
  "status": "active",
  "assigned_at": "ISO-8601",
  "review_at": null,
  "source_message_id": "message-123"
}
```

Пример Task:
